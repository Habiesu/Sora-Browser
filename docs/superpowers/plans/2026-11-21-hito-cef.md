# Hito CEF — cambiar el motor de Qt WebEngine a CEF

**Por qué:** Qt WebEngine 6.12 lleva Chromium 140; Chrome va por la 158. YouTube carga ~0,9 s más
lento que en Chrome y los parches de seguridad llegan tarde. CEF sigue a Chrome estable en días.
(Decisión del usuario, 21/11/2026; ver CLAUDE.md.)

**Qué se queda:** toda la interfaz en Qt Widgets (TitleBar, TabStrip, Toolbar, Omnibox, MainMenu,
BookmarksBar, FindBar, ventanas, incógnito, arrastre de pestañas), los datos (HistoryStore,
BookmarkStore, Settings, DownloadManager en sora.db) y el bloqueador adblock-rust.
**Qué cambia:** todo lo que habla con el motor (`Tab`, `Page`, perfiles, interceptor, `sora://`,
puente JS, descargas, extensiones, ventanas emergentes, menús contextuales, pantalla completa).

**Normas del hito:** pruebas primero (Qt Test); nada frena el arranque; textos en español; ramas y
subidas como siempre. Medir contra Chrome solo cuando el usuario lo pida.

## Decisiones técnicas (comprobarlas en la tarea 1 antes de seguir)

- **Binarios:** distribución oficial "Standard" de CEF para windows64 (cef-builds.spotifycdn.com),
  última estable; `scripts/fetch-cef.py` la descarga a `.cef/` (como `fetch-qt.py`). `libcef_dll_wrapper`
  se compila con el mismo MSVC.
- **Procesos:** `sora.exe` (navegador, Qt) + `sora-helper.exe` (renderer/GPU/utilidad, sin Qt) para
  que los subprocesos no carguen Qt. Sandbox: activado si `cef_sandbox.lib` enlaza con nuestro MSVC;
  si no, se documenta y se deja para después.
- **Bucle de mensajes:** `multi_threaded_message_loop = true` en Windows (CEF con su propio hilo UI;
  Qt sigue en el principal). Todo lo que vuelva de CEF a Qt pasa por `QMetaObject::invokeMethod`
  (cola). Alternativa si da problemas: `external_message_pump` con `CefDoMessageLoopWork` en un QTimer.
- **Incrustar:** cada pestaña es un `QWidget` nativo; el navegador CEF es hijo de su `HWND`
  (`CefWindowInfo::SetAsChild`) y se redimensiona en `resizeEvent`. Estilo de navegador: Alloy
  (sin la interfaz de Chrome) dentro del motor Chrome de CEF.
- **Perfiles:** `CefRequestContext` con `cache_path` = perfil normal; incógnito = contexto sin ruta.
- **Bloqueador:** `CefResourceRequestHandler::OnBeforeResourceLoad` → `RV_CANCEL` si adblock-rust lo
  bloquea. Corre en el hilo IO: nuestro motor ya es seguro entre hilos. El aviso al escudo va
  agrupado (como hoy). El script de YouTube: `OnContextCreated`/inyección al cargar youtube.com.
- **`sora://`:** `CefRegisterSchemeHandlerFactory` + `CefResourceHandler` (mismos HTML de recursos).
  Puente JS: `CefMessageRouter` (`window.cefQuery`) en lugar de QWebChannel; `sora.js` adapta
  `onSora` para que las páginas no cambien. Solo se registra para `sora://` (seguridad igual que hoy).
- **Resto:** descargas `CefDownloadHandler`; buscar `CefBrowserHost::Find`; imprimir `Print`;
  DevTools `ShowDevTools`; zoom `SetZoomLevel`; pantalla completa `OnFullscreenModeChange`; menú
  contextual `CefContextMenuHandler` (locale `es`); emergentes `OnBeforePopup`; reproducción
  automática con `--autoplay-policy` + lista de sitios; GPU dedicada (exportaciones) se mantiene.

## Riesgos

- Tamaño: CEF pesa ~250 MB descomprimido (Qt WebEngine ~200 MB).
- Memoria: CEF usa un proceso de GPU aparte, como Chrome (Qt lo tenía dentro del principal).
- Hilos: el hilo UI de CEF no es el de Qt; cualquier llamada cruzada mal hecha es un cuelgue.
- Linux: CEF+Qt en X11/Wayland se prueba aparte (más adelante).
